# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Read `../CLAUDE.md` first: it describes the surrounding workspace (independent repos, directory ↔ artifactId
mapping, cross-repo dependency propagation). This directory is `globs-shared` on disk but builds
`org.globsframework:globs-off-heap`, currently `5.8-SNAPSHOT`, against `globs` 5.6.0.

## Build & test

Java 22 source/target (local JDK is 25). No CI workflow and no `settings.xml` in this repo — resolution is
`~/.m2` or GitHub Packages.

```bash
mvn -o test                                  # full suite, ~2-3 min (SearchTest/TestShared are perf-heavy)
mvn -o test -Dtest=SearchTest                # one class
mvn -o test -Dtest=OffHeapHashServiceImplTest#withSameHash
mvn -o test-compile
```

Surefire runs with `useModulePath=false` (the Foreign Memory API + unnamed module). Tests are JUnit 5.
`FindPerf` is a JMH benchmark (`@Benchmark`, generated by the annotation processor on the test classpath);
there is no runner `main` and no shade plugin, so run it from the IDE or with an explicit classpath through
`org.openjdk.jmh.Main`. `OffHeapExample` is the README example as a `main`, not a test.

Several tests write to fixed paths (`/tmp/test`, `/tmp/testEmpty`, `/tmp/offheap-example`) and reuse them
across classes; newer ones use `Files.createTempDirectory`. Prefer the latter when adding tests — stale data
in the fixed directories has caused confusing failures.

## What this library does

Serializes `Glob`s into flat, fixed-stride records in memory-mapped files, addressed by byte offset, and
reads them back with zero copying beyond the `Glob` instance itself. Everything is derived from the
`GlobType` at startup; the per-record path is an array walk with `VarHandle`s.

Two independent storage families share the same layout/field machinery:

- **tree** (`mem/tree`) — write-once. `OffHeapTreeService.create(type)` → `declareUniqueIndex` /
  `declareNotUniqueIndex` → `createWrite(dir).save(globs)` → `createRead(dir, arena)`. Indexes are
  *implicit binary search trees* flattened to disk (see below).
- **hash** (`mem/hash`) — hash-table with in-place update. `OffHeapHashService.create(type)` →
  `declare(name, keyBuilder, size)` → `createWriter` / `createReader` / `createUpdater`. Records get an
  extra leading `long` slot (`__FreeId__`, injected via `OffHeapGlobTypeGroupLayoutImpl.create(type, withFirstLayout)`)
  used as a free/tombstone timestamp so the updater can recycle slots.

`mem/` at the root holds what both use: `DataSaver` (the writer), `DefaultOffHeapReadDataService` (the
reader, which is also the `ReadContext` handed to every field accessor).

## The layout pipeline

Startup, once per `GlobType`:

1. `DataSaver.extractTypeWithVarSize` walks the type graph and collects every reachable type. Types reached
   through a `GlobField`/`GlobArrayField` *without* `@HeapInline` are **separate files**; with `@HeapInline`
   they are embedded in the parent's record.
2. `GroupLayoutFieldVisitor` (a `FieldVisitor`) turns the fields into a `java.lang.foreign.GroupLayout`,
   inserting explicit padding itself and naming each member after the field. Composite kinds get several
   named members, using the suffix constants on `DefaultOffHeapTreeService` (`_len_`, `_addr_`, `_set_`,
   `_date_`/`_time_`/`_nano_`/`_zoneId_`). Cycles are rejected.
3. `OffHeapTypeInfo.create` switches once per field to build a `HandleAccess[]`, each holding the
   `VarHandle`s resolved from the layout. `RootOffHeapTypeInfo` = primary layout + the inline sub-layouts.

Runtime: `save`/`readAtOffset` loop over `HandleAccess[]` at a record offset. Nothing reflects, nothing
re-resolves a handle. `IndexTypeBuilder` does the same for index records, but with `DataAccess`
(`compare` against a `FunctionalKey` directly in the segment, no `Glob` materialized) instead of
`HandleAccess`.

`OffHeapTypeInfo.byteSizeWithPadding()` — not `byteSize()` — is the record stride; record *n* lives at
`n * byteSizeWithPadding`.

## Encoding conventions to preserve

- **`isSet` vs `isNull` are encoded in sentinel values**, per field kind: strings write `-2` in the length
  slot for unset and `-1` for null; glob references write `-2L`/`-1L` in the offset slot; inline globs use a
  `_set_` byte (1 null, 2 unset). Any new `HandleAccess` must keep the distinction — round-tripping depends
  on it.
- **Strings are interned into one `strings.data` file**: `[int len][utf8 bytes]` repeated; records store
  `(addr, len)` and the reader caches decoded strings by address. `@MaxSize` strings are instead stored
  inline as a fixed `char[]` (or `byte[]` with `Heap7BitsString`) with no entry in the string file.
- **Annotations that drive layout** live in `mem/model` and follow the workspace's Glob-annotation pattern
  (`TYPE`/`UNIQUE_KEY`/`UNIQUE_GLOB`): `HeapInline` (embed instead of reference), `HeapMaxElement`
  (**required** on every `GlobArrayField` — its `maxSize` fixes the array stride), `Heap7BitsString`.
  Core `@MaxSize` and `@ArraySize` are also read.
- Files in a storage directory: `content.data_<TypeName>` (one per type, plus a `_<indexName>` suffix for
  hash index tables), `strings.data`, `<indexName>Unique.data`, `<indexName>Many.data`.

## Index representation

`DefaultOffHeapWriteTreeService` sorts keys into a `TreeMap` with `IndexFunctionalKeyComparator`, splits the
sorted array recursively (`Utils.split1Element`) into a balanced tree, numbers the nodes in pre-order, then
writes one index record per node holding: the key fields, `dataOffset1`, `dataLenOffset1`, and
`indexOffset1`/`indexOffset2` = the *record numbers* of the children (`-1` for none). Reading is a recursive
descent over those child numbers, comparing key fields in place.

`dataOffset1` is overloaded on the multi index: when `dataLenOffset1 == 1` it is the data offset directly,
otherwise it is an offset into `<indexName>Many.data`, an array of `len` data offsets. Unique indexes always
write `len == 1`.

`search(...)` (prefix search on the first *n* key fields) differs from `find(...)`: it descends with an
`EqualAt` (BOTH/LEFT/RIGHT) marker to collect the whole matching range, and applies a `Filter` for key
fields past the prefix.

## Adding a field kind

A new supported `DataType` needs, in order: a `visitXxx` in `GroupLayoutFieldVisitor` (with its padding), a
`HandleAccess` in `field/handleacces` (`create(GroupLayout, XxxField)` + `save` + `readAtOffset`, plus
`scanOffset` if it holds references to other records), a case in `OffHeapTypeInfo.create`, and — if it can
be an index key — a `DataAccess` in `field/dataaccess` plus a case in `IndexTypeBuilder` (which otherwise
falls back to `AnyDataAccess`). Fields also need to be handled in `DataSaver.extractGlobToSave` /
`scanForString` when they can contain nested globs or strings.

## Arenas and lifecycle

The caller owns the `Arena` and passes it to `createRead`/`createReader`/`createUpdater`; the services map
files into it and never create their own (`a4ddde0` deliberately removed a per-index arena). `FileChannel`s
are closed right after `map` — the mapping outlives them. Closing the arena invalidates every `Glob` field
still pointing into a segment, so a read service must not outlive its arena.
